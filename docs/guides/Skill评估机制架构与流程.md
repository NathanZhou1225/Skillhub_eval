# Skill 评估机制 — 架构与流程

> 受众：产品经理、业务负责人

Skill 提交后，经门禁校验、材料补齐、用例执行与双模型评审，输出 Pass / Warn / Fail 准入结论。

---

## 1. 系统架构

```mermaid
flowchart TB
    subgraph 接入层
        B1["对话页"]
        B2["API / CLI"]
    end

    subgraph 业务内核
        C1["对话编排"]
        C2["评估状态机"]
        C3["门禁：格式 / 安全 / 风险锁定"]
        C4["缺口扫描 & 补题计划"]
    end

    subgraph 执行与评审
        D1["沙盒 / 本地 Agent 执行"]
        D2["代码断言"]
        D3["双模型评审"]
    end

    subgraph 数据层
        E1["原稿区 originals（只读）"]
        E2["练习区 staging（可写）"]
        E3["评估留痕"]
    end

    B1 & B2 --> C1 --> C2
    C2 --> C3 --> C4
    C2 --> D1 --> D2 --> D3
    C2 --> E1 & E2 & E3
```

| 层 | 职责 |
|----|------|
| 接入层 | 上传压缩包、对话补材料、查看报告 |
| 业务内核 | 编排全流程；评估进行中锁定包版本 |
| 执行与评审 | 跑测试用例 → 确定性格式校验 → 双 AI 语义打分 |
| 数据层 | 原稿保留作者提交内容；练习区承载补题与评估副本 |

**设计原则**：先代码断言、后 AI 评审；双模型独立打分、互相不可见；refusal / adversarial 类用例失败一票否决。

---

## 2. 评估主流程

```mermaid
flowchart TD
    A(["提交 Skill 压缩包"]) --> B["格式检查 Level 0"]
    B -->|"不合规"| F1(["Fail"])
    B --> C["材料安全扫描"]
    C -->|"拦截"| F2(["Fail — 安全阻断"])
    C --> D{"测试题是否齐全?"}
    D -->|"缺题"| P["补题计划 → 作者确认"]
    P --> D
    D -->|"齐全"| E["初评 readiness\n结构 + 安全门槛"]
    E --> F["正式评估"]
    F --> G["执行用例"]
    G --> H["代码断言"]
    H -->|"红线 / 格式全错"| F3(["Fail"])
    H --> I["双模型并发评审"]
    I --> J{"聚合决策"}
    J -->|"达标"| PASS(["Pass"])
    J -->|"模型分歧 / 边界项"| WARN(["Warn → 人工裁定"])
    J -->|"综合分或红线不达标"| F4(["Fail"])
    WARN --> L{"专家裁定"}
    L -->|"批准"| PASS
    L -->|"退回"| F4
```

| 阶段 | 方式 | 产出 |
|------|------|------|
| 格式检查 | 规则引擎 | 包结构与元数据合法性 |
| 安全扫描 | 静态规则 | blocked / pass |
| 补题 | 缺口扫描 + 作者确认 | staging 测试用例 |
| 初评 | 结构 + 安全门槛 | readiness 结论（无 AI 打分） |
| 正式评估 | 执行 + 断言 + 双模型 | 三维质量分、完整度分、终态 |

**三维质量分**（加权 0–100）：指令遵循度 40% · 输出合规性 30% · 业务解决度 30%。完整度分独立呈现，不计入质量加权。

## 3. 提交侧交互流程

```mermaid
sequenceDiagram
    participant 提交方
    participant 对话界面
    participant 评估引擎
    participant 评审模型

    提交方->>对话界面: 上传压缩包
    对话界面->>评估引擎: 格式 + 安全门禁
    alt 缺测试题
        评估引擎-->>对话界面: 补题计划表
        提交方->>对话界面: 确认 / 代写 / 重传
    end
    评估引擎-->>对话界面: 初评结果
    提交方->>对话界面: 补全材料
    Note over 评估引擎: 条件满足后自动触发正式评估
    评估引擎->>评审模型: 并发评审
    评审模型-->>对话界面: Pass / Warn / Fail
    opt Warn
        评估引擎-->>对话界面: 冻结，等待专家裁定
    end
```

- 评估运行中不可更换包，保证结果可追溯。  
- Warn 挂起后续操作，待专家 Approve 或退回。  
- 评估改动仅写入练习区，原稿区保持不变。
