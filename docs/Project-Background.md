# SkillHub · 项目背景

> 设计背景摘要；总账与 Sprint 见根目录 `RECORD.md`、`.cursor_memory/active/SPRINT_skillhub-mvp.md`。

---

## 业务背景与痛点

公司在推进 AI 能力落地时，呈现 **参差不齐、各自为战** 的现状，可归纳为三维：

| 维度 | 痛点 |
|------|------|
| **认知门槛高** | 多数员工缺乏 AI Workflow / Agent / Skill 背景，有现成技能也不知如何上手 |
| **资产碎片化** | 各部门按边界沉淀 Skill，散落各处，缺乏统一整理、归纳与共享 |
| **质量无标准** | Skill 质量好坏参半，无统一规范与评审；好用难发现，劣质可能误导业务 |

---

## 核心诉求与 MVP 目标

SkillHub MVP 不是单纯的「技术仓库」，而是 **重运营、重标准、低门槛** 的内部产品。

| 目标 | 说明 |
|------|------|
| **平台建设** | 全员可分享、交流、互相引用的内部 SkillHub |
| **降低门槛** | 让非技术、非 AI 背景员工也能轻易使用 Skill |
| **规范探索** | 对标 OpenAI / Anthropic / Google 等头部规范，建立内部评审与上架标准 |
| **评判机制** | 多模型交叉验证的「评审 Agent」+ 统一准入流程；考核指令遵循度、输出合规性、业务解决度，以客观数据确立质量底线 |

**设计原则（与调研对齐）**：摒弃复杂业务分类的长尾规则；统一「一刀切」核心评估维度；弱化按技术栈（API / Python）分类，强化业务场景分类（见阶段三）。

## 四阶段路线图（设计任务）

| 阶段 | 核心目标 |
|------|----------|
| **一** | 技能资产准入规范 + 自动化质检机制（质量底线） |
| **二** | MVP 闭环验证 + 评判模型调优（提交→验证→上架） |
| **三** | 前端交互 + 集市生态（降门槛、场景分类、LUI、数据驱动推荐） |
| **四** | 立项提案 + 商业价值呈现（痛点映射、Demo 走查） |

详见 `RECORD.md` 任务拆分与 Active Sprint 清单。
